# 工作状态协议

本仓库的注入、采集和 TypeTree 诊断容易跨越多个小时。为避免把实验过程、实际结论和下一步假设混在一起，每次工作只保留以下三类状态：

1. **代码状态**：当前分支、未提交文件和构建结果。
2. **运行状态**：MUMU、目标包、注入阶段、会话目录和进程内存。
3. **证据状态**：`.hook`、`events.ndjson`、`.ttbin` 及其分析结果；没有文件或字段证据时标记为 `blocked`，不以进程存活或日志中的“成功”代替。

## 快速检查

在仓库根目录执行：

```powershell
& '.\tools\Show-HookStatus.ps1'
```

它只读检查工作区和进程，并将机器可读结果写到被 Git 忽略的 `artifacts/status/latest.json`。需要管道处理时使用：

```powershell
& '.\tools\Show-HookStatus.ps1' -Json -NoWrite
```

不使用 PowerShell 时可双击 `tools/Show-HookStatus.bat`；它同样只做状态检查，不会重启 MUMU。

## 阶段边界

- `配置已解析`：路径、Profile、VM 和输出目录已经确定，不代表目标包已启动。
- `运行时注入`：CLI 正在启动 MUMU/加载桥接库，不代表已进入游戏场景。
- `运行时监听`：目标包已运行，工具正在等待实际回调或 Transfer 证据。
- `会话产物`：只有看到 `.hook`、事件记录或 TypeTree 文件，才能说明相应阶段确实产生了数据。
- `字段级成功`：必须有非空、可解码的字段节点；RTTI 数量、文件大小和进程存活不能替代字段证据。

## 维护规则

- `artifacts/` 只存本机实验产物，不提交 Git；每次实验使用独立会话目录。
- 先运行状态检查，再决定是否重启 MUMU；没有证据表明注入失败时不重复启动。
- 结论写入 `docs/diagnostics/`，记录输入、命令、观察结果和阻塞点；不要用截图文件名代替结论。
- 一个实验只改变一个变量。登录时机、Profile、运行库和解析布局不要在同一轮同时修改。
