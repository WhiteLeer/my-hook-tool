# HSR 4.5 Runtime TypeTree Milestone

## Scope

This note records the HSR 4.5.0 MuMu experiments that produced non-empty,
field-valid runtime TypeTrees. It does not claim that serialized values,
`sourceFile#PathID`, Material-to-Shader identity, or RenderDoc EID binding have
been recovered.

## Confirmed

- `Light` (PersistentTypeID 108) was generated by the native runtime path with
  187 nodes. The field validator reports 187 non-empty type names, 187
  non-empty field names, 186 resolved parents, and zero missing or invalid
  indices/sizes.
- `Material` (PersistentTypeID 21) was generated by the same opt-in native
  path with 76 nodes. Its schema contains `m_Shader`, `m_ShaderKeywords`, and
  the saved-property texture PPtr fields, including their FileID/PathID
  children. The field validator reports zero structural errors.
- `Shader` (PersistentTypeID 48) was generated by the same native entry point
  with 1551 nodes. The field validator reports 1551 non-empty type names,
  1551 non-empty field names, 1550 resolved parents, and zero missing or
  invalid indices/sizes.
- The three runs completed without a guest crash. They used the HSR 4.5
  ARM64 runtime companion built from the current TypeTreeRipper source.

## Provenance Boundary

- The Light and Material experiments also observed real Transfer callbacks for
  their selected classes.
- The Shader run's `ripper-logcat.txt` shows the dumper calling the verified
  native TypeTree transfer slot and validating the 1551-node tree. Its session
  event stream reports no Shader Transfer callback. Therefore the artifact is
  accepted as a runtime-generated schema, but not as evidence that a live
  Shader object was transferred in that session.
- The `.hook` status must preserve this distinction. A non-empty TypeTree is a
  schema artifact; it is not an object identity record.

## Not Proven

- No captured field value has been proven to be an AS `sourceFile#PathID`.
- No Material object's `m_Shader` PPtr value has been directly linked to a
  Shader runtime object in the same call chain.
- No runtime Material/Shader object has been directly linked to a RenderDoc
  EID. Names, addresses, event order, low-bit matches, hashes, and ResourceId
  are not accepted as substitutes.

## Next Experiment Gate

Use the verified Material TypeTree only as a decoder contract. In one bounded
Material Transfer callback, capture the already observed serialization context
and a field/PPtr read only after a version-checked function boundary is found
by static disassembly. Accept a relation only when the same call chain carries
the Material object, the decoded field value, and the serialized identity
record. Do not enable another Vulkan export Hook variant.
