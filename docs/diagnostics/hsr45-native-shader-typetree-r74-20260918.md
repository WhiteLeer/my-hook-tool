# HSR 4.5 native Shader TypeTree (R74)

## Result

R74 produced and strictly decoded a non-empty runtime Shader TypeTree from the
HSR 4.5.0 Unity guest. Together with the previously validated R56 Material
tree, this confirms runtime field-schema acquisition for these two selected
classes. It does not establish live Material/Shader object references or an
asset identity bridge.

## Confirmed

- MuMu main process `MuMuNxMain` reported responsive and ADB
  `127.0.0.1:16384` returned `sys.boot_completed=1`; HSR was advanced from its
  title prompt into the overworld. No VM restart was needed.
- R74 used `ObserveVtableOffset=0xA0` for the Shader Transfer observer while
  enabling native TypeTree acquisition. The guest emitted
  `runtime/typetree/release.ttbin` at 150,991 bytes, SHA-256
  `3423bf6c24f08f83082caf4feae5baeba79da59c78c184e805eafb49169eb987`.
- The strict decoder identifies Unity revision `2019.4.34 Runtime`, Shader
  PersistentTypeID 48, 1,551 nodes, and `fieldIntegrity.status=valid`.
- The R56 Material tree is independently validated: PersistentTypeID 21,
  76 nodes, valid field integrity. The merged two-tree file decodes to 1,627
  nodes total: Material 76 and Shader 1,551, both valid.
- The merged output is byte-identical to the existing profile composite:
  both are 79,082 bytes with SHA-256
  `774d886d2309f26ed7b7ea11bd0b1e8cf37953fbbbbaf017a86a7cfe0b295851`.
  Thus merging is structurally verified, but the artifact adds no new bytes
  relative to that baseline composite.

## Observed

- R74's finalized hook contains 166 records, including 79 Shader Transfer
  events and one native TypeTree artifact. The captured session does not
  establish that the TypeTree was generated by a particular overworld action.
- R74 analysis reports zero AS Material/Shader records, zero explicit
  associations, zero serialized identity producer/resolve calls, and zero
  RenderDoc EID contexts.
- R73 is not negative evidence for TypeTree availability: it incorrectly
  configured both the observation slot and native TypeTree slot at `+0xA8`.
  Its 31-byte output is an invalidly triggered capture, not proof that Shader
  TypeTree data is absent.

## Blocked

- No live `Material.m_Shader` value, exact Material-to-Shader runtime object
  edge, `sourceFile#PathID`, AS-index identity join, or RenderDoc EID join has
  been established.
- The two statically identified direct callers of the `m_Shader` serializer
  were not observed executing in R71/R72. Their tested triggers are rejected;
  they are not proven globally unreachable.

## Next Gate

Do not repeat the R71/R72 static serializer callers or use character-page
co-occurrence as a binding. The remaining feasibility gate is the live load
boundary: identify a version-matched call that carries a typed serialized
owner/identity and its returned Material or Shader object in the same
invocation. If that boundary cannot be proven from the HSR 4.5 binary and
existing runtime evidence, keep the identity bridge explicitly blocked rather
than assigning semantics to opaque values.
